## Summary

---

## Root Cause Chain

```
prisma/schema.prisma
  └─ output = "../src/generated/prisma"     ← custom Prisma client output path

src/generated/prisma/ does NOT EXIST in source template
  └─ src/lib/db.ts: import { PrismaClient } from '../generated/prisma'
       └─ TS error: "Cannot find module '../generated/prisma'"
            └─ db is typed as: any
                 └─ db.roadmapNode.findMany() → any[]
                      └─ .map((p) => ...) → p: any (implicit)
                           └─ cascade: ~65 TS7006/TS7031 errors across all route handlers and pages
```

**Additional root cause:** `next-env.d.ts` is excluded from version control (in `.gitignore`) but the `tsconfig.json` includes it. Without it, there is no CSS module type declaration, causing `import './globals.css'` to fail in `src/app/layout.tsx`.

## Fix Applied

### Fix 1 — Prisma type stub

**File created:** `src/generated/prisma/index.d.ts`

A development-time type stub providing:
- All **13 enum types** as TypeScript string union types
- All **23 model interfaces** with scalar fields and relation shapes
- All **12 junction table interfaces**
- `PrismaClient` class with typed model delegates for all 23 models
- Each delegate: `findMany() → Promise<T[]>`, `findFirst() → Promise<T | null>`, `findUnique()`, `count()`, `create()`, `update()`, `upsert()`, `delete()`, `deleteMany()`, `updateMany()`, `groupBy()`

**Why this resolves all cascade errors:**  
With `db.roadmapNode.findMany() → Promise<RoadmapNode[]>`, every `.map((p) => ...)` callback has `p: RoadmapNode` explicitly. TypeScript no longer infers `any`.

**Important:** This stub is overwritten by `prisma generate` on first install. It is a source-level placeholder only.

### Fix 2 — CSS module declarations

**File created:** `src/types/css.d.ts`

Declares `*.css` as a module so `import './globals.css'` is accepted by TypeScript. Covers the gap while `next-env.d.ts` has not yet been generated by `next dev`/`next build`.

## Relation Shape Decisions

Several component types define their own local interface shapes (e.g., `WarningList.tsx` uses `Warning` with `relatedLog: { id: string; title: string } | null`). The stub was aligned to make `ArchitectureWarning` assignable to those shapes:

| Field | Stub type | Reason |
|---|---|---|
| `ArchitectureWarning.relatedLog` | `ExecutionLog \| null` (non-optional) | Component requires `{ id: string; title: string } \| null`; `ExecutionLog` is structurally compatible; `undefined` breaks assignability |
| `ArchitectureWarning.relatedRoadmapNode` | `RoadmapNode \| null` (non-optional) | Same reasoning |
| `ExecutionLog.tags` | `LogTag[]` (non-optional) | Component requires `Tag[]` where `Tag = { tag: {...} }`; `LogTag` satisfies this structurally |
| `ConversationArtifact.chronologyOrder` | `number` | Field exists in schema (`@default(0)`); missing from initial stub |

## Notes for Future Maintainers

1. **The stub is intentionally committed.** It allows `tsc --noEmit` to pass in CI before the install script runs `prisma generate`. After `prisma generate`, the stub is replaced by the real generated client.

2. **If the schema changes** (new model, new field, new enum), update `src/generated/prisma/index.d.ts` to match until the next `prisma generate` cycle.

3. **`next-env.d.ts` is not committed** (it is in `.gitignore`) per Next.js convention. The `src/types/css.d.ts` file covers CSS type declarations for pre-build typecheck.

4. **Strict mode is on.** The stub uses `unknown` for query args (not `any`) where possible, and `eslint-disable` only where necessary.
