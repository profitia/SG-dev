## Delivered behaviour

The existing primary browser language initializes persisted communication_language: pl/pl-* maps to pl, other primary languages to en. The stored communication preference determines whether a vocative applies. No nationality is inferred. A later explicit language preference has priority over browser initialization.

SQL006 permanently stores first_name, first_name_source, name_vocative, name_gender, name_resolution and name_dictionary_version. Registration attempts resolve the signed name before the first Clerk OTP is prepared; verified completion copies the winning attempt into the Finished profile. Subsequent mail uses the stored profile. Changing language recomputes eligibility, so English never uses a stale Polish vocative.

For a reviewed PL entry, Marek becomes “Cześć, Marku!”. EN retains “Hello, Marek!”. Unknown, conflicting or unreviewed names use the supplied first name and Unknown lexical gender. A missing name produces “Cześć!” or “Hello!”. The dictionary-derived gender is lexical metadata, not verified personal gender. It never determines assistant avatar: a male name with a chosen female assistant remains female in the email.

Email enqueue freezes first name/vocative with language/avatar. Retries and delayed events cannot replace that snapshot. Terminal outbox rows erase names along with encrypted email payloads. Pending name metadata follows abandoned-draft cleanup. Unbound invitations retain their existing neutral fallback. No organisation membership, entitlement or authorisation change is introduced.
