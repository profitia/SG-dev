# Profitia Developer Lifecycle Specification v1.1

Status: ACTIVE

Primary contract: `Canon/v3.0-profitia-agent-execution-canon.md`

## Lifecycle

`project selection -> manifest load -> repository/code-state/routing preflight -> pmos:begin -> execution -> validation -> pmos:save -> PMOS runtime-context refresh -> MEMOROS/PHR policy -> persisted-evidence verification -> closeout`

The lifecycle is project-agnostic and profile-driven. For SG2 it applies only when `TARGET_ENVIRONMENT = development`; Staging and Production tasks use their environment and release evidence without PMOS registration or closeout. `pmos:begin` and final closeout are separate transactions. Parallel registrations are allowed; the pending artifact is reserved only for serialized final closeout. Runtime health and historical estate debt are independent gates.

For every new managed task, pass the actual chat/thread ID to preflight as `--host-conversation-id` and to `pmos:begin` input v2 as `hostConversationId`. When the host exposes no stable ID, use `--host-conversation-unavailable` and explicit `hostConversationId: null` in the input. PMOS derives a distinct `conversationId` from the registered project and `taskId`; use the returned value in the matching final artifact. A second task in the same chat begins with a new task ID, not a new chat, a forged host ID, or a reopened completed record. Existing v1 registrations remain valid only for exact replay/recovery.

VECTOR is not in this lifecycle. Historical VECTOR and ETAP fields are compatibility input only. PMOS derives its own runtime context from PMOS authority.

## Read-only work

A managed read-only Development audit loads the same governance and uses `pmos:begin`, but performs no repository, runtime, schema, data, deployment, or infrastructure mutation. It closes with factual audit evidence. It publishes to PHR only if the audit establishes an accepted decision or baseline. An SG2 Staging or Production audit creates no PMOS history.

## Recovery

Recovery resumes the same registered task and same closeout evidence. It may replay idempotent PMOS, MEMOROS, or PHR operations. It may not create a replacement pending artifact, second continuity store, or synthetic completion facts.
