## 1. Purpose and boundaries

Platform Source Hub is a shared backend capability for external-provider acquisition, not a separate end-user application. It centralizes reusable provider authentication, transport, capability discovery, rate limits, normalized errors, source normalization, provenance and licensed reuse. It does not own host UI, conversations, business relevance or product workflows.

| Owner | Responsibility retained |
| --- | --- |
| Architecture Platform / Source Hub | Provider adapters, acquisition, transport receipts, source identity/provenance, licensed caching, provider usage facts and capability catalogue |
| Architecture Platform / Newsfeed | User observations/subscriptions, monitoring schedule, publication history, observation-context deduplication, private notification inbox, authorized consumer distribution |
| Insights Domain | Business relevance, ReportEvidenceBundle, report composition/review/publication and product scheduling; no duplicate provider adapter |
| Forecast Core | Canonical mathematical models, calibration, backtesting, predictions and verification measures |
| Benchmark Domain / Market Data | Canonical series, instrument/underlying identity, accepted market data and Macrobond authority |
| Identity/E1, Source/Root, Package & Limits | Existing identity, per-operation authorization/admission and commercial policy; Hub consumes their contracts |
| SG Runtime, SRM, CIC / AppShell | Existing host UI, login, assistant and consumer responsibilities under their own owners |

Trading Economics observations and forecasts are external evidence. They cannot silently replace Macrobond series, Forecast Core input, D7 predictions or its verification mathematics. A vendor symbol is not accepted instrument equivalence; preserve CFD/OTC, futures/spot, contract expiry, rollover, units, currency, session and quote/settlement distinctions. Benchmark/Market Data accepts mapping; Forecast accepts any change to canonical mathematical inputs. Hub cannot self-approve either.

## 2. Provider and consumer model

NewsAPI already has an accepted implementation in Newsfeed. GDELT, Trading Economics and Brave are future providers; this stage does not implement, call or admit them. Procurement Insights / Oil Market Outlook and other modules are future consumers, each requiring explicit versioned adoption and operation admission. No blanket “all providers/all consumers” grant follows from reuse.

The accepted NewsAPI connector and NewsDiscovery 0.1.0 stay in `apps/newsfeed-runtime/**` and `packages/newsfeed-contracts/**` byte-for-byte. No copy, move, wrapper implementation or duplicate transport is introduced. A later separately accepted extraction must name old/new owners and contract versions, parity/negative consumer tests, provider bindings, rollback and deprecation; only then may responsibility become physically shared. A business proposal is not a functioning Hub dependency.

## 3. Independent contract families

[Family catalogue](registries/platform-source-hub-contract-families-v1.json) proposes **News Discovery, Economic Calendar, Market Observations, Indicators and External Forecasts** with independent payloads and versioning. Only metadata/provenance is shared. Do not force these into one universal payload or reinterpret vendor fields as an unrelated family's values.

A minimal shared envelope identifies family/version, provider/API version, vendor record/source reference, retrieval and availability time, `asOf`, licence, quality, fingerprint and usage receipt. Unknown times remain explicitly UNKNOWN; retrieval time is not publication/availability time. Native payload extensions preserve source semantics without breaking existing consumers. A changed semantic interpretation requires a new version and producer–consumer acceptance.

News Discovery describes articles and publishers. Calendar keeps actual/previous/revised, consensus and vendor forecast distinct, with reference period and point-in-time revisions. Market Observations preserves instrument semantics. Indicators preserves frequency, units and vintage. External Forecasts identifies vendor/model/origin/target/horizon; it is never presented as Forecast Core output or assigned our verification scores. Missing is not zero; empty, partial, denied, unavailable and unsupported are different outcomes.

## 4. Provider capability catalogue

For each provider/API family, publish available request filters separately from result metadata. Record filter meaning, values/range, evidence kind/ref/date, entitlement and limitations. Catalogue states: DOCUMENTED, OBSERVED, UNVERIFIED, UNSUPPORTED, ENRICHMENT_REQUIRED. Native filtering, returned fields and later enrichment must be distinguishable. HTTP acceptance alone is not proof that a filter affects results; reject unsupported requests rather than silently dropping filters.

In particular, publisher country, headline edition and event geography are different. An article mentioning a region is not geolocated event evidence. Current NewsAPI capabilities and measured limits remain in the accepted [catalogue](../apps/newsfeed-runtime/docs/newsapi-capabilities.pl.md) and [evidence](../apps/newsfeed-runtime/docs/newsapi-live-evidence.json); do not promote unverified Polish filtering, plan limits or geographic inference to supported facts. No new provider capability is verified by Stage 1B.

## 5. Provenance, licensing and costs

Keep stable `sourceRecordRef`, original source/vendor identifiers, version/revision, URLs, retrieval/available/as-of times, raw-to-normalized lineage and fingerprints where licensed. Consumers reference source records and separately own their business evidence bundles. Unknown or stale data must carry explicit quality and freshness states.

A licence/admission record governs access, retention, cache, quotation, derived use and redistribution per provider, family, entitlement and consumer. Publicly reachable metadata is not automatically reusable licensed content. Cross-tenant shared public artifacts require explicit compatible licence and entitlement; deduplication cannot expand rights. Private user sources and query intent never enter a global cache.

Use existing Package & Limits admission/reservation/idempotency. Source Hub records actual provider usage once, retries and unknown-cost outcomes honestly; consumers account for their own subsequent business work. Cache hits are not additional paid retrievals. No guessed quota, unlimited retry, zero-cost timeout or second commercial-policy engine.

## 6. Identity, private data and API security

Resolve organization, effective actor and operation from **server-verified E1 context** on every operation, including background work and exports. Preserve ownership versus authorship. A peer credential authenticates transport; it does not grant business access. Validate environment, caller/consumer, operation, delegation, current revocation, entitlements and cost before acquisition or read; deny when unavailable. Never trust client-supplied organization/user IDs for authorization or create a parallel Identity engine.

Keep public/licensed source artifacts separate from private request ledgers, query text, observations, recipients and usage linkage. Private partitions/cache keys must bind verified environment, consumer, organization, effective user and relevant licence/admission version. Shared artifact lookup must still enforce access and redaction. Future tests must cover two organizations, users, cross-environment replay, revoked/expired delegation, retry and denied jobs. No global private result cache.

Provider credentials remain server-side, separated by environment and entitlement. No provider key, DB URL/password, authorization header, private query or full payload in source, logs, telemetry, PMOS or PHR. Use separate ordinary runtime and migrator roles; no database owner/BYPASSRLS in runtime. TLS in transit; bounded requests, retries/timeouts, idempotency and safe error messages. Future arbitrary-URL acquisition additionally requires SSRF/redirect/egress controls before admission.

The planned API is service-authenticated, without a UI. Public HTTPS transport, if selected, remains closed to unauthenticated callers and validates M2M plus E1; private networking alone is not authorization. Do not route across environment isolation using public fallback. Existing E1/Source/Root contracts remain mandatory; no grants or operation-access rows are created here.
