## Decision and ownership

The owner's 2026-10-19 instruction authorizes the previously proposed independent Maps application, without embedding it in SRM. Register Maps Capability as the logical owner of `apps/maps-runtime/**`, `packages/maps-contracts/**`, and `packages/maps-embed/**`. Its independent provider configuration, browser-origin security boundary and release lifecycle justify deployment separation. SRM and SG2 consume its public contracts; neither imports the other's private source.

`maps-runtime` owns map rendering, marker selection and the Google adapter. `maps-contracts` owns framework-neutral, versioned location and event schemas. `maps-embed` supplies an explicit lifecycle and host adapter. An iframe is a rendering mechanism, not the reuse contract. An independent host harness must exercise the contract before supported reuse is claimed.

## Provider boundary

An explicit narrow exception to section 2.4 permits Google's browser-only Maps JavaScript SDK inside Maps Runtime, using a dedicated website-restricted and API-restricted browser key. That key is delivered to browsers by design. Server credentials, MGBI payloads, identity tokens and tenant data must never be included in public configuration or URLs. The Maps SDK must preserve Google's built-in attribution.

Server geocoding belongs to `apps/maps-runtime/src/server/google/`, using separate server credentials, fixed upstream destinations, bounded payloads, timeout and no automatic retry after uncertain delivery. Google-derived data is projected and retained only as permitted by the applicable terms. Provider response text never becomes executable HTML.

## Domain and E1 boundary

Maps accepts generic locations. SRM retains canonical supplier identity, registry provenance, organization-owned location records and all persistence. Registry data and private manual locations remain separate. A user is the author, an organization the owner. Google project IDs are environment infrastructure, not business organization IDs.

Host-supplied IDs or display capabilities do not authorize operations. Current E1 server context and adopted operations remain mandatory for private reads, writes and billable business operations. Existing embedded read/command channels may carry only authorized host projections. Do not extend or bypass protected E1 contracts in this slice. Missing Maps/location operation rights remain explicitly unsupported until coordinated E1 adoption.

## Initial connector slice and release

The initial standalone Development slice renders a real Google map and synthetic markers, exposes configuration/readiness and a host harness, and validates provider failures. It does not read MGBI, store customer locations, expose unauthenticated geocoding, or mount anything in SRM. Real provider checks, mocks, E1 tests, persistence tests and deployment are separate evidence categories.

New deployments use the verified Development provider identity, manual deployment and no attached product database. Record exact source, configuration and artifact evidence plus executable rollback before deployment. First bootstrap has no predecessor artifact: explicitly record the absent-resource baseline and verified containment/removal procedure; never invent a prior digest. Subsequent releases require a retained working artifact. Staging and Production require separate authorization.

CI must validate contracts, independent host mounting, provider failures, security boundaries, routing and the application build. SRM PMOS/PHR records belong only to the SRM continuity profile, with MEMOROS disabled.
