# SG2.0 Mandatory Canonical Routing Guard

Use this block before every SG2.0 task that may create, modify, move, delete, or deploy source-controlled behavior.

```text
# SG2.0 — MANDATORY CANONICAL ROUTING GUARD

Before any source mutation:

1. Work from canonical repository authority:
   - repository: profitia/SG-dev
   - branch authority: fresh origin/main
   - canonical workspace: /Users/tomaszuscinski/Documents/Visual Code Studio/SG-dev-main

2. Load and obey:
   - Canon/v1.0-current-architecture-development-canon.md
   - Canon/registries/current-architecture-baseline-v1.json
   - Canon/v1.0-post-migration-architecture-state-and-change-classification-canon.md
   - Canon/v1.0-repository-routing-and-module-ownership-canon.md
   - .github/copilot-instructions.md

3. Resolve routing in this exact order:

   OBSERVED SURFACE
   -> CAPABILITY
   -> LOGICAL OWNER
   -> EXACT CANONICAL PATH
   -> EXACT BASELINE PATH STATE
   -> CHANGE CLASSIFICATION
   -> AFFECTED DEPLOYMENT(S)

4. Mandatory rules:

   - Deployment identity is NEVER source ownership.
   - Render service names/URLs are deployment metadata only.
   - Baseline state is ALIGNED or LEGACY.
   - TRANSITIONAL is a separate change classification and does not change owner.
   - cleanupFindings are advisory and do not create write targets.
   - Most-specific registered path classification wins.
   - LEGACY is NOT a default write target.
   - Default legacy rule: READ FROM LEGACY — WRITE TO CURRENT CANONICAL OWNER.
   - A legacy write requires an explicit LEGACY_WRITE_EXCEPTION naming the exact path.
   - Reuse an existing canonical owner by default.
   - Do not create a new first-class app/tooling/module/deployment owner because ownership is unclear.
   - Unknown, NO_MATCH, or CONFLICT routing fails closed.

5. Special routing that MUST NOT be collapsed:

   Forecast runtime/API orchestration
   -> apps/sg-runtime

   Forecast mathematical/statistical compute/methodology
   -> tooling/Benchmark-Forecasting

   Forecast presentation/visualization
   -> apps/dashboard-preview

   Benchmark Finder / Category Builder / benchmark APIs
   -> apps/sg-runtime

   PCOS shared contracts
   -> packages/pcos-contracts

   Governance source contracts
   -> packages/governance/src only for actual governance work

6. Known nested LEGACY paths:

   - apps/dashboard-preview/prisma-market-data/**
   - apps/dashboard-preview/lib/benchmark-forecast/runtime-query.ts
   - apps/pcos-explorer/prisma/schema.prisma

   Do not write to these by default.

   apps/dashboard-preview/lib/benchmark-forecast/runtime-query.ts
   may receive a minimal bridge-local fix only when the task explicitly authorizes:

   LEGACY_WRITE_EXCEPTION =
   apps/dashboard-preview/lib/benchmark-forecast/runtime-query.ts

   Other legacy writes require their own explicit exact-path exception.

7. PMOS guard:

   Ordinary PMOS source may route to apps/pmos.
   PMOS conversation/recovery/pending/runtime-context/history artifacts are not ordinary feature source.

8. Before implementation, output exactly:

ROUTING_GATE
Observed surface =
Capability =
Logical owner =
Canonical write path =
Baseline state = ALIGNED / LEGACY
Nested legacy override = YES / NO
Change classification = TRANSITIONAL / NOT_APPLICABLE / UNRESOLVED
Cleanup finding involved = YES / NO
Affected deployment(s) =
Legacy consulted = YES / NO
Legacy write exception = NOT_REQUIRED / REQUIRED_AND_AUTHORIZED / REQUIRED_NOT_AUTHORIZED
New first-class module proposed = YES / NO
ROUTING_GATE = PASS / BLOCKED

9. STOP CONDITIONS

Return ROUTING_GATE = BLOCKED and do not mutate source if:

   - logical owner is ambiguous;
   - exact target path is NO_MATCH or CONFLICT;
   - a new first-class owner would be required but is not explicitly approved;
   - a LEGACY write is required but no exact-path exception is authorized;
   - a deployment identity is being used to infer source ownership;
   - the requested change crosses multiple owners but the task does not explicitly separate them.

Only after ROUTING_GATE = PASS may the task execute its actual implementation instructions.
```
