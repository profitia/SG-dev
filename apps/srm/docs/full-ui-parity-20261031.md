## Warunki kontrolowanej integracji

1. Oddzielny PR producenta SRM oraz PR konsumenta SG2. Konsument przyjmuje dokładny commit i digest pakietu producenta. Wszystkie poprzednie receipts pozostają niezmienione; nowe przyjęcie jest dodatkiem.
2. Obecny trusted-main kontroler CI SG2 nie dopuszcza `@profitia/maps-embed` / `@profitia/maps-contracts`. Lokalny precheck zwraca `PRIVATE_MANIFEST_PIN_MISMATCH` i `PRIVATE_PACKAGE_ALIAS_REJECTED`. Właściciel polityki musi przeprowadzić zwykłe rozszerzenie dopuszczonych lokalnych zależności; polityka nie została zmieniona.
3. Lokalny build SG2 używa odizolowanej kopii istniejących, zgodnych wersją i integralnością prywatnych pakietów. Nie jest to dowód czystego `npm ci` SG2. Czysta instalacja wymaga istniejącej kontrolowanej ścieżki CI i zaufanych poświadczeń.
4. `/api/config` istniejącego Maps Development potwierdza konfigurację i listę hostów bez `https://dev-sg2.spendguru.app`. Przed odbiorem mapy potrzebne jest kontrolowane dopisanie tego originu bez usuwania istniejących wpisów.
5. Nie wykonano deploymentu SRM/SG2/Maps. Wymagane są zakończenie aktywnych pomiarów FRESH Codexa A, exact-SHA CI, właściwe zatwierdzenia release oraz zweryfikowany retained LKG (artifact ID + digest i konfiguracja/plan odtworzenia). Sam SHA nie zastępuje artefaktu rollback.
6. Staging, Production i oba piloty pozostają poza zakresem. Nie zmieniono silnika finansowego, E1/Clerk, polityk RLS, schematu, routingu dostawców ani limitów/licencji. Nie pobierano finansowych PDF MGBI.
