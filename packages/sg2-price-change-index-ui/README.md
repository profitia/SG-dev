# Price Change Index UI

React 18 presentation module for SG2. Import the named PriceChangeIndex export and supply view, typed data, theme and optional onAction/onThemeChange callbacks. The demo owns synthetic datasets and in-memory action history. The module has no product transport, session, router, database or external theme connection. Shadow DOM contains its original styles and portals; no host-wide CSS reset is installed. Consumers supply local Inter/Roboto font assets.

Changing resetKey remounts the view and clears its transient demo projection. Unmount through the host React root. Each instance has its own presentation scope and listeners. onAction emits view, interaction/save/theme kind and the source action label; it is a presentation intent, never proof of persisted business work. Callback adapters for real APIs and authorization are Stage 2. No arbitrary-host compatibility, iframe, postMessage or automatic MagicPath synchronization is claimed.

All three pinned revisions and the approved shared library are in src/provenance.ts. Version 1/2 dark modes and canonical theme controls are explicitly approved additions. Inspector: hover an element and press Control+I, Escape closes it. Missing source IDs are reported as missing, never invented.

The `content` prop can override `headerTitle` (versions 1/2), `homeTitle` and `homeDescription` (version 3). Default copy remains the pinned design. Product names, categories, suppliers, source histories, scenarios and calculations are supplied through typed `data`. Entry-seed generation and supplier examples live in the demo fixtures. No tenant, user or PORR identity is embedded in the UI core.

Font fidelity is version-specific because the source environments differ: versions 1/2 render native Inter 3.019 with real static weights; version 3 imports Inter regular and synthesizes its heavier weights. The demo bundles the exact 3.019 TTF faces under SIL OFL, plus the pinned modern Inter regular/Roboto assets, and loads the appropriate faces on a full route entry. An adopting host must supply matching font faces; multiple versions with conflicting font registrations need host-level font isolation. This is an explicit reuse boundary, not a claim of compatibility with every host.

Owner-approved deviations: dark variants and C95 control for versions 1/2; current-library action minimum height 32px/font 12px takes precedence over v3's 38px/13px fallback. Legacy C95 controls float at the 65.625rem header breakpoint with canonical 1rem edge clearance, preserving source header flow. Escape, focus trapping and focus return in the v3 component dialog implement the shared dialog canon without changing its visible layout. Inspector metadata describes pinned provenance and declared rules; it is separate from direct component reuse or live synchronization.

The source export expects a React 18 host and a compatible TypeScript/Vite build with Tailwind 4, its Vite plugin and `tailwindcss-animate`; `?inline` style imports are part of this build contract. The supplied independent test host demonstrates that contract. Another bundler needs a build adapter or a separately packaged artifact. Legacy in-module navigation emits `onNavigate({view,screen})` and scrolls only its presentation surface. The standalone demo handles its own window scroll; an adopting host retains control of its own navigation and viewport.

Native C27 dialogs acquire an instance scroll lock and emit `onScrollLockChange(locked)`. A host whose scrolling container sits outside the module supplies this optional callback and applies its own scroll policy. The standalone demo temporarily locks its own page body and restores the previous value on release. The module locks its presentation surface, reference-counts concurrent locks and releases them on close, reset or disposal. It does not set another application's document-body styles. Hosts mounting multiple instances coordinate outer-container locks per instance.

Pinned rem geometry assumes a 16px document root. Media queries and fixed/modal geometry follow the host viewport. An adopting application with a different root scale or a narrow embedded container needs an explicit layout adapter and its own acceptance checks. The current stage verifies the standalone demo and the supplied minimal host; it does not implement an iframe or a container-query conversion.

The optional `onThemeChange(theme)` callback lets the host reflect the module mode in its own viewport/native controls. The standalone demo owns and restores its document color-scheme; the independent minimal host preserves its original document styles.

The module reuses the pinned library C07 compact dropdown (32px height,12px text,8px radius), in a48px row. Its8px top/bottom insets and independent horizontal navigation preserve all options and state across resizes. Desktop uses the original native selector. Original hidden source declarations remain in the provenance matrix alongside this explicit approved overlay.
